# Baton — Failover & Handoff (the heart of the product)

Baton's differentiator is the **relay**: one task, one context, and when a provider hits
its usage limit, the next provider continues automatically **without losing state**.
Everything in this file is on the critical path. Build it defensively and test it with
fixtures — never against live accounts in CI.

## 1. Limit detection (LimitDetector)

Three layers, evaluated in order. First match wins.

**Layer A — structured signals (most reliable):**
- Claude: the **`rate_limit_event`** line of the stream (verified in 2.1.241) — a
  `rate_limit_info.status` outside the healthy set means blocked, and `resetsAt` gives an
  exact reset time for the hint. Plus: final envelope with `is_error: true` and
  limit-related result text; abnormal exit paired with limit text on stdout/stderr.
- Codex: `turn.failed` event — inspect its error payload.
- Gemini: `error` object in the json envelope; HTTP-ish codes surfaced in messages
  (`429`, `RESOURCE_EXHAUSTED`).

**Layer B — pattern tables (regex over stdout+stderr, case-insensitive):**
Shipped defaults (seed list — MUST be refreshed from real captures during M5):

```jsonc
{
  "claude": [
    "usage limit reached", "rate limit", "limit reached\\b.*resets?",
    "You've reached your", "5-hour limit", "weekly limit"
  ],
  "codex": [
    "usage limit", "rate limit", "429", "You've hit", "too many requests",
    "quota"
  ],
  "gemini": [
    "RESOURCE_EXHAUSTED", "quota exceeded", "429", "rate limit",
    "Quota exceeded for quota metric"
  ]
}
```

Rules:
- Defaults live in code; `~/.baton/patterns.json` **extends** them (never replaces) so
  users can patch new wordings the same day a provider changes copy, without an update.
- Every default pattern must be backed by a fixture file proving it matches a real
  captured output (`fixtures/<id>/limit*.txt`). No fixture → no pattern.
- Extract a reset hint when present (e.g. "resets 7pm", "try again at …") into
  `resetHint` — best-effort string, no strict parsing in v1.

**Layer C — heuristics (last resort):** immediate non-zero exit (<3s) with network-ish
or overload-ish stderr → classify `unknown`, not `limit`. Unknown errors do NOT trigger
the relay by default (avoid infinite loops on a broken repo state); they stop with a
clear message and `--relay-on-error` opts in.

**Classification output:** `{ kind: "limit" | "auth" | "not_installed" | "crash" |
"unknown", raw, resetHint? }`. `auth` and `not_installed` never relay — they print the
fix (the provider's own login/install command) and mark the agent unavailable for this
run.

## 2. Cooldown ledger

When agent X hits a limit, record `{ agent, ts, resetHint }` in `~/.baton/usage.json`.
For the next `cooldownMinutes` (config, default 30; overridden by a parsed resetHint if
clearly longer), the Router and FailoverEngine skip X unless it's the only agent left —
then ask the user. `baton status` shows cooldowns prominently.

## 3. Relay algorithm

```
task arrives → agent A chosen
run A
  ├─ done → persist turn, finished
  ├─ limit →
  │    1. persist partial turn (endedBy: "limit")
  │    2. write cooldown entry for A
  │    3. generate HANDOFF.md (below) from SessionStore + git
  │    4. next = first agent in chain after A that is: detected ✓, not cooling ✓
  │       (chain default: ["claude", "codex", "gemini"], config-overridable
  │        per project; `--chain codex,claude` CLI override)
  │    5. none available → print all cooldowns + soonest reset hint, exit code 3
  │    6. announce relay in UI:  ⚡ claude hit its limit → passing the baton to codex
  │    7. run(next) with prompt = RELAY_PREAMBLE + original task
  └─ error → classify; stop with remedy (or relay if --relay-on-error)
Max relays per task: `maxRelays` (default 2). Loop protection: never relay to an agent
that already hit a limit for this same task.
```

`RELAY_PREAMBLE` (exact string, keep stable — it's part of Baton's identity):

```
You are taking over an in-progress coding task from another AI agent that hit its
usage limit. Read the file HANDOFF.md in the project root first, then continue the
task from where it stopped. Do not restart completed work. Do not ask for
confirmation; this is a non-interactive run — proceed and report what you did.
```

## 4. HANDOFF.md — exact template

Generated by `HandoffWriter` on every relay, on `baton handoff`, and refreshed after
every successful turn (cheap insurance). Target length ≤ ~800 words — a briefing, not a
transcript. Written at the **project root** (agents naturally read files there), and
`.baton/HANDOFF.md` keeps the latest copy too.

```markdown
# HANDOFF — <ISO timestamp>

## Task
<the original user task, verbatim>

## Status
- Previous agent: <id> (stopped: usage limit | completed turn)
- Relay count for this task: <n>/<maxRelays>

## Done so far
<bulleted rolling summary from SessionStore — what was actually accomplished,
in past tense, concrete>

## Files touched (git)
<output of `git status --porcelain` + `git diff --name-only`, deduped;
"(not a git repo)" if applicable>

## In progress / next steps
<what the previous agent was doing when it stopped + remaining steps>

## Constraints & decisions already made
<stack choices, style rules, anything a fresh agent must not re-litigate>

## How to verify
<the test/build command(s) that must pass, e.g. `npm test`>
```

Generation rules:
- Source of truth is `SessionStore` + live git commands — never re-ask an LLM to write
  the handoff in v1 (costs a turn on an account that may be at its limit).
- Rolling summary maintenance: after each `done`, append the turn's `resultSummary`;
  when the summary exceeds ~2,500 chars, compress oldest entries into a terse digest
  (pure string logic, no LLM).
- Handoff must be deterministic given the same store + git state (snapshot-testable).

## 5. `baton continue`

Manual counterpart of the automatic relay: regenerates HANDOFF.md and dispatches
"continue the task" to (a) same agent via native resume if available and not cooling,
else (b) the next agent in the chain with the relay preamble. This is the command users
reach for the morning after hitting a nightly limit.
