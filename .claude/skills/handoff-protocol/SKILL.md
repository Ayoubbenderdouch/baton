# Handoff protocol

The template, preamble text, and generation rules live in docs/FAILOVER.md §3–4 and are
NORMATIVE — copy from there, don't paraphrase from memory.

## Invariants
- Deterministic: same store + same git state → byte-identical HANDOFF.md (snapshot
  tested). No timestamps inside sections other than the header line.
- ≤ ~800 words. It's a briefing for a fresh agent, not a transcript. If it grows,
  compress the "Done so far" digest — never truncate "In progress / next steps".
- Never generated by calling an LLM in v1 (the account may be at its limit — that's
  exactly when we need it).
- Written at project root AND mirrored to .baton/HANDOFF.md. Refreshed after every
  successful turn, not only on relays.
- RELAY_PREAMBLE is a stable string constant with its own test; changing its wording is
  a breaking change requiring a CHANGELOG entry.

## SessionStore rules
- Append-only turns; rolling summary compressed by pure string logic past ~2500 chars.
- promptPreview ~200 chars, resultSummary ~500 chars — enforce at write time.
- Corrupt/absent session.json must never crash a command: warn, start fresh, keep the
  corrupt file as session.json.bak.

## When changing anything here
Update the snapshot fixtures deliberately (review the diff — a snapshot update IS the
API change), including the Arabic-content snapshot, and verify on windows-latest.
